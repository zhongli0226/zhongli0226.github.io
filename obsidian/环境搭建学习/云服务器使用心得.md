# 前言

这篇笔记记录我对云服务器用途的一些重新理解。

以前虽然很早就了解过云服务器，但一直没有明确知道它能用来做什么。当时玩 `Minecraft` 时曾经想和朋友一起组服务器，但因为人数没有凑起来，所以没有真正搭建。后来玩《幻兽帕鲁》时，也只是使用游戏自带联机；如果只有两个人一起玩，确实没有必要专门使用云服务器。

最近因为 AI 工具和 Agent 的使用越来越多，我对云服务器有了新的认识：它不仅可以用来部署游戏服务器，也可以作为远程运行环境、代理中转节点、网页端应用部署环境，以及个人 AI 服务的承载平台。

# 背景介绍

云服务器本质上是一台可以远程访问的 Linux 或 Windows 主机。相比本地电脑，它更适合承担长期在线、固定 IP、远程访问和自动化执行的任务。

在我目前的使用场景里，云服务器主要承担以下几类作用：

- 运行 `Codex`，让 Agent 可以直接在远程服务器上执行任务。
- 部署个人 AI 服务，例如 `AstrBot` 机器人。
- 作为个人静态网站或其他服务的中转入口。
- 尝试语音服务器、游戏服务器等需要长期在线的服务。

其中最重要的一点是：把 Agent 放到服务器中运行后，后续很多部署、配置和维护工作都可以交给它辅助完成。

# 核心思路

我现在使用云服务器的思路可以概括为三步：

1. 先准备一台网络环境合适的云服务器。
2. 在服务器上安装 `Codex`，让它具备远程自动化执行能力。
3. 再围绕个人需求部署具体服务，例如 AI 机器人、网页中转、语音服务或游戏服务器。

> [!NOTE]
> 如果主要依赖 `Codex` 或其他需要访问外部服务的 Agent，服务器的网络环境会直接影响使用体验。原文中使用的是日本 IP 的服务器，因为国内 IP 服务器可能无法正常使用相关能力。

# 操作步骤

## 步骤一：选择合适的云服务器

如果服务器主要用于运行 AI Agent 或部署依赖外部 API 的服务，建议优先考虑海外服务器。

我当前选择的是日本 IP 的云服务器，原因是国内 IP 的服务器在使用 `Codex` 时可能无法正常工作。服务器具体配置可以根据用途决定：

- 只运行轻量服务时，低配置服务器也能满足基本需求。
- 如果要同时运行多个服务，需要关注 CPU、内存和磁盘空间。
- 如果要对外提供访问，最好确认是否有公网 IP，以及安全组和端口开放规则是否方便配置。

## 步骤二：在服务器上安装 Codex

在服务器中安装 `Codex` 后，后续很多服务部署工作都可以让 `Codex` 辅助完成。

安装命令如下：

```shell
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

由于云服务器通常没有图形化界面，登录时需要使用设备授权方式：

```shell
codex login --device-auth
```

登录完成后，可以回到桌面版 `Codex`，通过 `SSH` 连接远程云服务器。连接成功后，就可以在桌面端直接控制远程服务器上的 `Codex`。

![Codex 连接远程服务器示意图](https://cdn.jsdelivr.net/gh/zhongli0226/PicGoCDN/img/20260627133012.png)

## 步骤三：部署个人 AI 服务

服务器也适合部署一些个人 AI 相关服务。

我目前搭建了一个 `AstrBot` 项目服务，可以在 `QQ` 上使用机器人进行对话聊天。具体搭建过程可以参考 [[AI机器人云服务器搭建]]。

这类服务适合放在云服务器上的原因是：

- 服务可以保持长期在线。
- 不依赖本地电脑是否开机。
- 后续维护可以通过 `SSH` 或 `Codex` 远程完成。

## 步骤四：搭建网页或服务中转

云服务器还可以作为中转服务使用。

例如，我在 `GitHub` 上搭建了个人静态网页，但由于国内访问 `GitHub` 可能不稳定，可以考虑利用云服务器作为中转入口，将个人静态网站转发到服务器 IP 地址上。

类似地，如果存在需要统一转发或代理的订阅链接，也可以把云服务器作为中转节点。不过这类服务需要结合实际网络环境、服务条款和合规要求来配置，不能只关注“能不能访问”。

![服务器中转服务示意图](https://cdn.jsdelivr.net/gh/zhongli0226/PicGoCDN/img/20260627133153.png)

## 步骤五：尝试更多长期在线服务

除了 AI 服务和网页中转，云服务器还可以部署一些需要长期在线的个人服务。

例如：

- 部署 `TeamSpeak`，和朋友进行高质量语音开黑。
- 部署游戏服务器，例如多人联机游戏服务。
- 托管其他个人工具或网页端应用。

这些内容目前只是可扩展方向，本文不展开具体部署步骤。

# 常见问题

## 国内服务器无法正常使用 Codex

如果服务器 IP 位于国内，`Codex` 可能无法正常使用。原文中的解决思路是选择海外 IP 的云服务器，例如日本 IP 服务器。

## 云服务器没有图形化界面

云服务器一般通过命令行管理，因此不能依赖浏览器窗口完成登录。安装 `Codex` 后，应使用下面的设备授权方式登录：

```shell
codex login --device-auth
```

## 桌面端连接远程 Codex 的基本思路

完成服务器端登录后，可以在桌面版 `Codex` 中通过 `SSH` 连接远程云服务器。连接前需要准备好服务器的基础登录信息：

- 云服务器的 `SSH` 地址和端口。
- 本地 `SSH` 密钥或密码登录方式。
- 桌面版 `Codex` 中远程连接入口的位置。
- 连接成功后的验证方式。

连接成功后，就可以在本地桌面端操作远程服务器上的 `Codex`，适合继续完成后续服务部署和配置。

# 总结

云服务器的价值不只在于“部署网站”或“开游戏服”。在 AI 工具逐渐普及之后，它更像是一个长期在线的远程工作环境。

目前对我来说，最有价值的用法是先在服务器上安装 `Codex`，再让它辅助完成后续部署和维护工作。这样云服务器就可以逐步扩展成个人 AI 服务、网页应用、中转服务和长期在线工具的运行平台。
